# Keenetic: Discord и Smart DNS

Заметки о настройке Keenetic с Entware и nfqws2 для работы голосовых каналов Discord и доступа к сервисам OpenAI через Smart DNS. Это описание проверенной настройки одного подключения; результат зависит от провайдера, версии KeeneticOS и конфигурации nfqws2.

Для самостоятельной диагностики с помощью Codex на Keenetic Viva и Kakadu VPN: [задание для агента](CODEX_AGENT_INSTRUCTIONS.md).

## Перед началом

- Нужны Keenetic с настроенным [nfqws2 для Keenetic](https://github.com/nfqws/nfqws2-keenetic) и SSH-доступом к Entware. Команды ниже относятся к роутеру, а не к PowerShell на компьютере.
- Сохраните резервные копии конфигурации Keenetic, `nfqws2.conf` и списков. Убедитесь, что знаете, как восстановить их, если потеряете связь.
- Не публикуйте пароли, токены, конфигурацию VPN, логи с персональными данными или личные IP-адреса.
- Проверяйте результат без полного VPN: иначе запросы могут идти по другому маршруту и не показать состояние домашнего подключения.

## Smart DNS для OpenAI

Для проверки использовался [MagicDNS](https://magicdns.ru/). Сначала проверьте доступность поставщика и его актуальные адреса: сторонние узлы могут менять IP, испытывать перегрузку или перестать работать. Краткая проверка не гарантирует бесперебойную работу.

На проверенном Keenetic домены OpenAI были направлены на узел `109.120.132.43` с помощью DNS-over-TLS; остальным доменам оставлены прежние DNS-серверы. Пример команд Keenetic CLI:

```text
dns-proxy tls upstream 109.120.132.43 853 sni dns.magicdns.ru domain chatgpt.com
dns-proxy tls upstream 109.120.132.43 853 sni dns.magicdns.ru domain openai.com
dns-proxy tls upstream 109.120.132.43 853 sni dns.magicdns.ru domain oaistatic.com
dns-proxy tls upstream 109.120.132.43 853 sni dns.magicdns.ru domain oaiusercontent.com
system configuration save
```

Поддержка доменно-зависимого DoT зависит от версии KeeneticOS и установленных компонентов. Проверьте действующую конфигурацию командой `show dns-proxy` и запросами к DNS роутера: перечисленные домены должны разрешаться через нужный узел, а обычные сайты — продолжать открываться. Проверьте вход, приложение и длительные соединения, а не только открытие главной страницы. Выбирайте DNS и прокси, которым доверяете: их оператор видит запрашиваемые имена и метаданные соединений.

На нашем подключении автоматический список nfqws2 содержал домены OpenAI. После добавления следующих доменов в `/opt/etc/nfqws2/lists/exclude.list` обрывы Codex в коротком наблюдении прекратились:

```text
chatgpt.com
openai.com
oaistatic.com
oaiusercontent.com
```

Добавляйте только отсутствующие строки, предварительно сохранив файл. В nfqws2 обычная запись домена также охватывает поддомены; соответствие зависит от используемых профилей и их списков. Не удаляйте остальные исключения. [Документация zapret2](https://github.com/bol-van/zapret2/blob/master/docs/manual.en.md) описывает работу списков и их автоматическое перечитывание.

## Если Discord открывается, а голосовой канал зависает

Проверьте журнал Discord и найдите этап отказа. В исследованном случае управляющий WebSocket к `discord.media` на нестандартном HTTPS-порту сбрасывался до подключения голоса; это не было доказательством проблемы с UDP. Сравнение показало, что соединение проходило без конкретной TCP-стратегии nfqws2.

В существующей конфигурации `NFQWS_ARGS_CUSTOM` был профиль:

```text
--filter-tcp=2053,2083,2087,2096,8443
--hostlist-domains=discord.media
--lua-desync=fake:blob=tls_clienthello:repeats=12:fooling=ts
--new
```

На проверенном подключении помогло удалить **только строку `--lua-desync=fake:...` из этого профиля**, оставив фильтр, `--new` и следующие профили на месте. Это не универсальная стратегия: без соответствующего профиля или при другой причине сбоя менять его не нужно. Сохраните резервную копию, проверьте синтаксис и перезапустите nfqws2 только после подготовки отката. Затем проверьте подключение к голосовому каналу, звук в обе стороны и работу YouTube.

## Откат

Восстановите сохранённые копии конфигурации и списков nfqws2 и перезапустите его штатным способом. DNS Keenetic восстановите по резервной копии конфигурации или удалите только добавленные настройки через CLI/панель, затем сохраните конфигурацию. Удаление DoT-сервера по адресу и порту может удалить и другие записи с тем же сервером; сначала проверьте текущие настройки.

## Ограничения

Smart DNS может помогать только для поддерживаемых доменов и не устраняет все сетевые блокировки. Положительный HTTP-ответ, соединение с голосовым сервером или несколько минут без сбоев не доказывают стабильность в течение дня. Если проблема проявляется снова, сохраните точное время и диагностируйте тот этап, на котором возникла ошибка.
